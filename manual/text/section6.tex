\textbf{The two tables worth opening.} \texttt{game\_features.parquet} has one row per collected
game and holds the measures the model may see. \texttt{game\_scores.parquet} has one row per scored
game, 545 modelled plus 424 held out for the survivorship comparison, and holds the score under
both weightings, the two components, the band and the per-game attributions. It is the file the
website reads. Both are parquet rather than CSV so column types travel with the data:

\begin{cmd}
python -c "import pandas as pd; print(pd.read_parquet('data/processed/game_scores.parquet').head())"
\end{cmd}

\textbf{The result tables.} The nineteen CSV files in
\texttt{data\textbackslash processed\textbackslash tables} are one per reported analysis, and every
number in the research report traces to one of them. Three data dictionaries alongside them
document every column in both parquet files.

\textbf{What is not redistributed.} Collected review text stays in \texttt{data\textbackslash raw}
and is not published. Steam's terms permit collecting review data, not republishing the corpus, so
any public release carries derived game-level features and the collection code only. Author
identifiers are hashed at the cleaning stage, which is pseudonymisation rather than anonymisation.
